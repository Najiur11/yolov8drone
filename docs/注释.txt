✅ 文件 1：build_docs.py
    用途：自动化构建 MkDocs 文档并后处理 HTML
    功能总结：
    使用 MkDocs 构建主文档和多语言版本。
    自动克隆并同步 hub-sdk 仓库内容到文档中。
    构建后处理 HTML 文件，如：
    移除 .md 后缀的链接。
    更新页面标题（如 404 页面）。
    更新“编辑此页”链接，指向 GitHub 源文件。
    最终输出本地服务器命令，便于本地预览。
    适用场景：
    文档发布前自动化构建。
    多语言文档同步更新。
    保证 HTML 链接正确性和可编辑性。

✅ 文件 2：build_reference.py
    用途：自动生成 API 参考文档（Reference）
    功能总结：
    扫描 ultralytics 包下所有 .py 文件。
    提取每个文件中的类（class）和函数（def）。
    自动生成对应的 .md 文件，包含类/函数的 API 文档。
    自动生成 mkdocs.yaml 的导航结构（nav）部分。
    适用场景：
    自动生成 API 文档，避免手写。
    保持文档与代码同步更新。
    构建开发者友好的参考手册。

✅ 文件 3：coming_soon_template.md
    用途：占位页面模板，用于“即将发布”的文档页面
    功能总结：
    提供统一的“施工中”页面风格。
    包含关键词、描述、社交媒体链接、用户反馈入口等。
    用于尚未完成的功能或文档页面占位。
    适用场景：
    新功能开发中但文档需提前上线。
    保持用户预期管理，避免 404 或空白页。

✅ 文件 4：mkdocs_github_authors.yaml
    用途：Git 提交邮箱到 GitHub 用户名的映射表
    功能总结：
    将 Git 提交历史中的邮箱地址映射为 GitHub 用户名。
    用于在文档中显示“作者”或“贡献者”信息。
    适用场景：
    自动生成贡献者列表。
    文档页面显示“谁写了这部分”。

✅ 文件 5：README.md
    用途：Ultralytics 文档项目的说明文档
    功能总结：
    介绍如何安装、构建、本地预览、部署文档。
    提供多语言构建、GitHub Pages 部署、开发模式安装等指南。
    包含社区贡献、许可证、联系方式等信息。
    适用场景：
    新贡献者入门指南。
    本地开发文档时的参考手册。
    项目对外说明文档。
